# 外部内容不进模型上下文，证据是唯一载荷

触发器整天读的是新闻、公告、文件内容、接口返回——全都是不该被模型看到的东西。这里说的「不该」不是权限问题（v1 单 owner），而是**注意力与可信度**问题：一旦原始数据进了上下文，模型就会开始对它们做推理、引用、转述，而它没有任何标记能区分「用户说的」与「某个网页上写的」。所以这条边界被做成结构性约束：**外部内容进入模型上下文的唯一入口是 `evidence`**，`text ≤ 200` 字符、`≤ 5` 条，合计约 1KB。

检查点因此落在三处，而且都在上游：`judge` 的返回值（唯一载荷，形状与上限由宿主强制）；`trigger_source` 的列举（`shape` 只给字段名与类型，真实值一律不回显——回显真实样例等于让外部内容顺着「调试工具」这条缝溜进主 loop，而主 loop 没有任何机制知道自己读到的不该被看到）；快照本身（只在内存，没有落盘路径，重启即空）。`history.jsonl` 只记 `detail`，不记证据正文。唯一的开口是 `trigger action=test`：它返回 evidence，但调用者正是此刻在写这条规则的人。

这条边界决定了另外几个设计。**快照不落盘、证据不留痕**：外部内容根本没有落盘路径，凭证与隐私一起被顺手解决。**TTL 之外的条目在视图里根本不存在**：既然模型不该看陈旧值，脚本也不该能读到它，于是「把昨天的天气当现状」在结构上不可能发生。**`judge` 不能调工具、不能现取数据**：否则「同一 tick 所有脚本看到同一瞬间」就破了，而且一次十几秒的 `web_fetch` 会把 tick 的毫秒级预算吃光。需要更多数据的正确做法是**加一个源**，不是放开读取。

**放弃的东西**：模型没法按需翻原始数据，所以凡是它能用来写规则的信息，都得靠 `output_schema` 事先声明、靠 `shape` 回显结构、靠 `test` 反复试。这让「写一条规则」的迭代成本高于「把数据丢给模型让它自己看」，也让「这条规则为什么这么写」的答案不在对话里而在两个脚本里。我们接受这个代价，因为另一条路——让模型按需读取全量外部数据——会让上面所有检查点变成摆设：只要有一条读取路径，"不进上下文" 就只是一句自我安慰。

**将来的逃生口**：若真的需要模型读原始数据，那应当是一次显式的、可见的读取（新的 agent + 新的工具 + 明确的用户确认），而不是把快照挂到 trigger 的沙箱外面。
