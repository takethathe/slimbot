# 记忆条目不写日期，年龄由快照序列反推

Dream 整理记忆时需要知道一条事实"跟了多久"来判断它是否过时。最直觉的做法是往每条记忆里写一个日期（`observed_date`，或在行尾标注 `← 21d`）。我们决定**记忆文档里一个日期都不出现**：日期由模型自己写就会被编造，而写错的日期比没有日期更坏——它会被下游当真实时间消费。取而代之，条目的年龄由**快照序列逐版本 diff** 反推：一条正文行首次出现在哪一次 Dream 快照，就从那一次的目录时间戳算起。时间信息全部留在系统侧。

**Considered Options**

- **行内 `observed_date` 字段**（票面 Q3 原案）：模型每写一条就要编一个日期，幻觉风险最高；且 `active`/`superseded` 状态与 `dream.md` 既有的"冲突就地替换、不保留两个版本"直接矛盾，检索侧也无消费者。整体出 v1。
- **文件 mtime 当"最后更新时间"**：`write_file_atomic` 是 temp + **rename**，mtime 永远是"最后被整理时间"而非"观察时间"——Dream 每跑一次就把全目录刷新，测出来的是"Dream 最近碰过"，不是"这条事实何时成立"。
- **git blame 逐行追年龄**（nanobot 的 `_annotate_with_ages()` + `GitStore.line_ages()` = dulwich blame 走的路）：上游最终把整个特性退订为 no-op 配置，因为 reviewer 预期"LLM reacts poorly to the `← Nd` suffix"，加固方式是"行数不一致就整体放弃注解"。我们不重走这条弯路，回滚粒度也只需要"整篇文档 × 单次 Dream"，git 的独特价值（逐行 blame、任意两点 diff、挑 hunk）恰好是不用做的那一半。
- **把反推出的年龄渲染进 `memory_read` 返回给 Dream 的文本**：一旦注解过的行成为 `memory_edit` 的匹配输入，模型会把 `← Nd` 抄回文件，"读时注解"固化成"文档内容"——这正是 nanobot 的翻车路径。否决。

**Consequences**

- 年龄推导依赖快照序列**连续**：中间被轮转掉的版本会导致年龄未知，此时标"未知"而不外推（对应 nanobot"行数不一致就整体放弃"那条加固）。
- 推导对**措辞改写**敏感：改写一条 bullet 会被算成新条目、年龄清零。因此反推的时间**只喂 Dream 的提示**（"以下条目首次出现于 N 天前"），不进文档、不进 `memory_search` 结果、不进 WebUI——一旦进检索结果，模型就会把它当"事实的一部分"复述（"根据记录，这条偏好始于三月"），那正是取消日期要避免的幻觉，只是换了来源。
- 年龄只由**正文行**的首次出现决定；**标题行的新增/改写/移动不改变年龄**（标题是索引锚点不是内容，否则每次重写章节名都把老记忆清零）。
- 标记清洗覆盖读写两侧：`memory_read` 返回零注解；`memory_write` 的 content、`memory_edit` 的 `new_string` 落盘前剥离已知年龄标记形态；且 `memory_edit` 的 `old_string` 在**匹配之前**就剥离——否则带后缀的 old_string 匹配不上 → `EditOutcome::NotFound` → Dream 反复失败。剥离规则收到最窄（仅行尾、仅已知形态、不碰句中），且剥离动作记 trace 不静默改写。
- 时间加权若将来要做（票 07 检索按年龄加权），用同一份快照序列重算，不新增存储。
- **重开条件**：若票 07 需要条目级溯源、或检索需按年龄加权且逐行 blame 是手搜（快照 diff）拿不出的能力，本决定应有正当理由重开。
